# Benchmark do agrupamento de transações

A é o caminho anterior às otimizações, B usa apenas `RETURNING`, C usa apenas agrupamento e D combina os dois. A partir de `tests/`:

```bash
env -u RUN_REAL -u RUN_E2E RUN_ATTEMPT_TRANSACTION_COMPARE=1 \
  node node_modules/vitest/vitest.mjs run --maxWorkers=1 unit/openai-attempt-registry-benchmark.test.js
```

Três rodadas por combinação. São 360 amostras a 1 ou 10 simultâneas, 450 a 50 e 600 a 100. Todas as 14.160 tentativas foram persistidas, com uma linha de Analytics por requisição e zero falhas de SQLite ou avisos do Registry. A resposta completa e as tabelas do Registry foram verificadas com fixtures sintéticas. A tabela inclui todas as combinações, em ordem de leitura. O harness alternou a ordem de execução dos modos.
